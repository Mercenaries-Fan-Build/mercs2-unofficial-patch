# BUG-014 — the billboard-tree Z-prepass draws with the previous draw's world matrix

**Status going in:** `built`. Ships in `unofficial_patch.asi`, source
[`bug_014_tree_zpass_matrix.c`](../native/src/bug_014_tree_zpass_matrix.c). Needs m2-sdk 0.5
(`m2_render.h`). See [README](README.md) for build and install.

Found in frame captures taken while investigating the *Blow It Up Again* DLC's "tearing", on Windows and on
macOS (Wine). **This is not that tearing's fix.** With this fix armed, the DLC's tearing remains: below the
horizon the screen stops being redrawn and earlier frames persist. That was the DLC port's converted terrain
data, fixed in the port's converter, not in the game. What this defect does on screen by itself is not
established. Its effect in the captures is that the tree Z-prepass
cards are drawn through another draw's world matrix.

## The defect

The billboard trees draw in three passes. The shadow pass and the colour pass each push an identity
world matrix before their trees. The **Z-prepass** loop (v1.1 `0x004A3EA0`, v1.0 `0x004A3E40`) pushes
none, and neither do its draws (`FUN_004A1D70`, `FUN_004A1F30`). Its packets (class 3, program `0x7E`)
therefore carry the matrix index last pushed before the loop. Its only caller (v1.1 `FUN_00468EA0`) runs
it after each object's draw and, for objects flagged for it, that object's occlusion box (`FUN_0046EDF0`).
In every capture taken before the fix, the last push was such a box: a unit cube scaled to an object's
bounds, 9× to 200×.

The matrix index is the only box-specific state that reaches the tree packets. The box also writes the
`+0x4C` word's global, but resets it to `0xFFFF` itself. The Xbox 360 build has no tree Z-prepass, and
its tree loops all push the identity.

## The fix

A detour on the Z-prepass loop makes the same push the shadow loop makes, then runs the original:

- `i = counter++`;
- copy the identity to matrix-table entry `(parity · cap + i)`;
- set the matrix index to `i` and the draw record to 1.

Every address comes from m2-sdk (`m2_render_tree_sites`), which finds both loops by signature. It
checks them against each other, against the frame stores and against the game's other matrix push,
and confirms the identity's 16 floats. The fix therefore arms on every build those checks pass, and
fails with the mismatch named on any other.

## Reproduce BEFORE

The defect is read from a frame capture, not from a view.

1. Set `BUG_014 = 0` in `unofficial_patch.ini`.
2. Install the `mercs2-profiler` ASI. In the DLC, stand where trees are in view, for example in the bar
   the first contract starts in.
3. Press **F6**, which writes `mercs2_profiler_frame_<n>.bin`. Run
   `mercs2_probe frame-capture <bin> <tsv>`: the class-3 tree packets sit on a matrix with a scale above
   1, and that matrix is also used by the box packet drawn just before them.

## Expected AFTER

- `unofficial_patch.log`:
  ```
  BUG-014: Z-prepass loop 004A3EA0, identity 00DFBBD0, matrix index 01163740, table 018C61E0 x 5120
  BUG-014  armed   — billboard-tree Z-prepass draws with another draw's world matrix
  ```
  (v1.1 addresses; v1.0 builds print their own).
- An F6 capture's class-3 tree packets each use a matrix the hook pushed: the identity, scale 1, used
  by no other draw family. This held for every capture taken with the fix armed on v1.1.
- **What must not change:** tree shadows, tree colour, occlusion culling and every other draw. The
  hook adds one identity matrix per frame, from the same table the game fills, and changes nothing
  else.

## What would count as overreaching

Trees missing from the Z-prepass (holes in the depth buffer where trees stand), or any draw other
than the class-3 tree packets changing in a frame capture.
