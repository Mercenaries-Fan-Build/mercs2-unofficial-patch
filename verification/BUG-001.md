# BUG-001 / BUG-003 — toolbox count inflates on reload

**Status going in:** `built`. Not yet `verified` — that needs the reproduce-before step below, on the
Windows box.

Ships as two `patch_lua` appends that must go together:
[`bug_001_toolbox_recount.lua`](../src/lua/bug_001_toolbox_recount.lua) (→ `mrxtaskobjectivedestroy`)
and [`bug_003_collecttype_loadassets.lua`](../src/lua/bug_003_collecttype_loadassets.lua)
(→ `mrxtaskjobcollecttype`).

## Reproduce BEFORE installing — this is the part that must not be skipped

A fix for a bug nobody watched fail is not a verified fix.

1. Load a save with some toolboxes already collected. Note the HUD count, `X/100`.
2. Drive a long way across Maracaibo — the point is to stream in a lot of world, so cover ground you
   have not visited this session.
3. Save, quit to desktop, relaunch, reload.
4. **Read the HUD count again. It should have gone UP** without collecting anything, by roughly the
   number of already-collected toolboxes that streamed in during step 2.
5. Repeat 2–4 once more. It should climb again — a few cycles walk it toward 100/100.

Also watch for, during step 2: milestone reward vehicles being granted, and cash arriving with the
`[Generic.Collectibles]` tag, both with no pickup.

### The signature that distinguishes THIS bug from a miscount

`tSaveData.tCollected` is a GUID-keyed set, so the saved list holds the **true** count while
`nCompletedToolboxes` (the HUD) climbs. **Save and HUD disagree.** That divergence is the tell, and
it also means the save data was never corrupted — only the stat.

If save and HUD agree, you are looking at something else and this fix will not address it.

### Faster loop

Logan's `lua-bridge` REPL (`127.0.0.1:27050`) can read the stat directly rather than squinting at
the HUD, which makes steps 1 and 4 exact instead of approximate.

## Install

```
qm build . --out build --corpus <workshop_data/lua>
```
then deploy `build/mercs2-unofficial-patch.wad` as `<game>/data/vz-patch.wad`.

⚠ This **rewrites** `vz-patch.wad`. That is intended here, but it means any other mod occupying that
slot is replaced — the engine mounts exactly one `<stem>-patch.wad` per base WAD.

## Expected AFTER

- Repeat steps 1–4. **The count does not move** across reloads.
- Collecting a NEW toolbox still increments it, still pays out, still advances milestones. This is
  the regression that matters: the guard only ever suppresses a GUID the objective was already told
  was complete, so a genuine pickup — which was never in `vTgtExclude` — must be unaffected.
- Save and HUD now agree.

## What was verified offline already

- Both appends compile into the resident block and the overlay re-reads clean.
- `wad_simulator` over the emitted WAD: `type_id 35 script consumed=643 issues=0`,
  **`VERDICT: Full consumption path completed without violations`**.
- These prove the WAD is structurally sound and the Lua is valid. They prove **nothing** about the
  counting behaviour — hence the in-game steps above.
